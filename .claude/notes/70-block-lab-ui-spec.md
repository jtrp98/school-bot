## ระบบรูปทรง/สีบล็อก และกฎ contrast

รูปทรง (R2):
- **hat** (เริ่มต้น / วนซ้ำ / ฟังก์ชัน): โดมครึ่งวงรีกว้าง ≤132 เหนือแถบหัว (ขนาดประมาณจากสายตา · OQ108) · "เริ่มต้น" และ "วนซ้ำ" มีอย่างละ 1 วางไว้ให้ในงานใหม่ ลบไม่ได้ (OQ26 · OQ39 เปลี่ยนชื่อจาก "วนทำซ้ำ")
- **c-block** (ทำซ้ำ / ถ้า): มีปาก · "ถ้า" มีปุ่ม เพิ่ม/เอาออก "ไม่เช่นนั้น" แบบไอคอน + ข้อความ ≥44
- **stack** คำสั่ง: มุมมน 7 + รอยบากบน เรียงต่อกันได้
- **value** ค่า: มน (pill) ใส่ในช่องกลม
- **boolean** เงื่อนไข: หกเหลี่ยม ช่องหกเหลี่ยมรับเฉพาะหกเหลี่ยม · วางค่ามนลงไม่ได้ → ช่องสั่นครั้งเดียว + "ช่องนี้รับเฉพาะเงื่อนไข"

สถานะ: ปกติ · ยังไม่ได้ต่อ (พื้นเรียบ `#F4F6F8` ขอบประ ไอคอน + ข้อความ · `#5A6377` บน `#F4F6F8` = 5.4:1 · ST-27) · ghost ตำแหน่งแทรก · เตือน (ขอบประเหลือง) · ช่องค่าว่าง (ไฮไลต์ + ไอคอน + ข้อความ ไม่ให้เริ่มจำลอง/ส่ง) · บล็อก "กำพร้า" ที่อุปกรณ์ถูกลบ (คงชื่อเดิม + ป้าย "ไม่พบอุปกรณ์ · ถูกข้ามตอนจำลอง" · OQ50) · ปิดใช้จากเมนู (OQ214: เทาจากผู้ใช้ ≠ เทาเพราะกำพร้า)

สีและตัวอักษร:
- ตัวอักษรและไอคอนบนบล็อก = text-primary `#14243D` 16px/700 ทุกหมวด (OQ135 ยกเลิกตัวขาว) · เกณฑ์ ≥4.5:1 บนพื้นหมวด (ต่ำสุดจริง 6.57:1 Car Control)

## Flow: เชื่อม UNO → ตรวจก่อนรัน (R17) → ส่งลงบอร์ด → Output/Serial

1. **เชื่อมบอร์ด** — ชิปบอร์ดในแถบหน้าต่าง: ยังไม่ได้เชื่อม → กำลังเชื่อม → เชื่อมแล้ว (พอร์ต) → สายหลุด · ปุ่ม "เปลี่ยน" เปิด `ConnectUnoA2` (OQ175) และถูกล็อกตอนกำลังส่งหรือกำลังเชื่อม · หน้าเชื่อม: สแกนบอร์ดอัตโนมัติเมื่อเสียบ/ถอด → การ์ดบอร์ด "ใช้ตัวนี้" → "เชื่อมต่อ" → ตรวจว่าบอร์ดตอบ → ตั้งชื่อบอร์ด (ข้ามได้) → กลับหน้าต่อบล็อกเองใน 2 วินาที · มีโหมด "หาด้วยการถอดสาย" เมื่อเจอหลายบอร์ด · กรณีพอร์ตถูกโปรแกรมอื่นใช้ (Arm Lab) / บอร์ดไม่ตอบ / ลองหลายครั้งมี checklist · Baud rate ตั้งตามบอร์ดอัตโนมัติ แก้เองไม่ได้ · สายหลุดระหว่างทำงาน = รอเสียบกลับและต่อให้เอง
2. **ตรวจก่อนรัน (R17)** — ตรวจใหม่ทุกครั้งที่กด "เริ่มจำลอง" หรือ "ส่งลงบอร์ด" (กดหยุดไม่ตรวจ) · เจอปัญหา → dialog `role=alertdialog` มาสคอตท่า #6 "คิดออก" + จำนวนข้อ + ลิสต์ (เห็นพร้อมกัน 3 ข้อ ที่เหลือเลื่อน) · 4 กรณีเรียงตามชนิด: (1) ยังไม่ได้วางอุปกรณ์/ช่องเลือกว่าง (2) ต่อสายไม่ครบ (3) บล็อกกับขาไม่ตรง (4) วงจรอันตราย · ต้นเหตุเดียว = 1 ข้อ · แต่ละข้อมีไอคอน + เลขข้อ + หัวข้อ + วิธีแก้ + รหัส `E-CHK-xx` (ชั่วคราว) + "ไปดู" · กดรายการ = ปิด dialog แล้วไฮไลต์จุดที่ผิด · Esc/ฉากหลัง = กลับไปแก้ · `mode=run` กด "เข้าใจแล้ว จำลองต่อ" ได้ (บล็อกที่อุปกรณ์ไม่ครบถูกข้าม มีป้ายตลอด) · `mode=send` ไม่มีทางข้าม · (เดิมมีชิป "ปัญหา N ข้อ" ในลิ้นชัก แต่ถูกเอาออก 2026-11-02 · ผลตรวจขึ้นเป็น popup ตอนกดเริ่มจำลอง/ส่งลงบอร์ดเท่านั้น) · ข้อความห้ามสื่อว่าวงจรปลอดภัย
   - โหมดโค้ดไม่ใช้ R17: กดเริ่มจำลอง/ส่ง = แปลงโค้ดก่อน · ไม่ผ่าน → ข้อความใน Output (กดไปที่บรรทัดได้) + แถบ "แปลงโค้ดไม่ผ่าน (บรรทัด N)" · ไม่ปิดกั้นปุ่มส่ง · ไม่มีตัวนับ syntax แบบ realtime (OQ161)
3. **ส่งลงบอร์ด** (R9) — มีปัญหา R17 → dialog mode=send · ยังไม่เชื่อมบอร์ด → การ์ด `nodevice` · ก่อนส่งมีการ์ด `warn` เตือนต่อสายจริงให้ตรงวงจร (เลือก "ไม่ต้องเตือนอีกในงานนี้" ได้ เตือนใหม่ถ้าวงจรเปลี่ยน) · แล้ว `compile` (ขั้นที่ 1 จาก 2) → `send` (ขั้นที่ 2 จาก 2 + เปอร์เซ็นต์) → `success` / `fail` (why=usb หรือ compile) · ระหว่างส่ง: เปลี่ยนบอร์ด/ออกจากหน้า/เปิดงานใหม่ถูกกันด้วย guard · บล็อกตัวละครไม่ถูกส่งลงบอร์ด
4. **หยุดทั้งหมด** (R9 · OQ79) — ปุ่มเห็นและกดได้ตลอด · การ์ด `stop0` = หยุดตัวจำลอง/ตัวละคร แต่ "โปรแกรมที่อยู่บนบอร์ด Uno อาจยังทำงานอยู่" (DEV-Q16 ยังไม่ตอบ) · ทางเลือก `stopA`/`stopB` = ส่งโปรแกรมว่างให้บอร์ด ("โปรแกรมเดิมบนบอร์ดจะหาย จนกว่าจะส่งโปรแกรมใหม่")
5. **Output/Serial** (`TerminalA2`) — หัว "ข้อความจากบอร์ด" + ป้ายแหล่ง (จากตัวจำลอง / จากบอร์ด Uno / อ่านไม่ได้) · เลื่อนตาม/หยุดเลื่อน · ล้าง · เก็บ 200 บรรทัดล่าสุด · มีสถานะ `uno-manual` ที่ต้องกดเริ่มอ่านเอง ("โปรแกรมบนบอร์ดอาจเริ่มใหม่") · ช่องพิมพ์ส่งเข้า Serial ใช้ได้เมื่อเชื่อมบอร์ดหรือกำลังจำลอง · Enter ส่ง · ↑ เรียกข้อความเก่า · ผลแปลงโค้ดไม่ผ่านแสดงที่นี่พร้อมลิงก์ "ไปที่บรรทัด N ในโค้ด"

สถานะจำลอง (pill หัวแผงขวา · ไม่แสดงตอนพร้อม): พร้อมจำลอง · กำลังแปลงโค้ด · กำลังจำลอง · แปลงโค้ดไม่ผ่าน · โปรแกรมจบแล้ว · หยุดเพราะแก้ไข · หยุด: ลัดวงจร · หยุด: LED เสีย · แก้โปรแกรมตอนจำลอง = หยุดเอง (R10) · เริ่มจำลองตอนแผงขวาหุบ = เปิดแผงเอง (OQ168) · LED กะพริบเกิน 3 ครั้ง/วินาที แสดงแสงคงที่กลาง ๆ (OQ34)

## Ver.1 vs อนาคต

ใน Ver.1 (A2) มีจริง:
- เป้าหมายเป็น board ตายตัว: หมวดตัวละครไม่แสดง (OQ80) · แผงตัวจำลอง/stage ซ่อนเป็นค่าเริ่มต้น (`panels=hide` · OQ102) แต่ยังมีปุ่มเปิดในชุดปุ่มแนวตั้ง
- โหมดบล็อก + โหมดโค้ด (R19) · ลิ้นชัก Output/C++ · ส่งลงบอร์ด · หยุดทั้งหมด · เชื่อมบอร์ด Uno · ผลตรวจก่อนรัน · เมนูคลิกขวา (ต้นแบบ)
- หมวดที่มีบล็อก: เริ่มต้น · ควบคุม · ตรรกะ · คณิต · ตัวแปร · ฟังก์ชัน · Sensor · Display · Serial
- ชิปคลาวด์แสดงเฉพาะผิดปกติ (OQ124 · OQ125)

ยังไม่ทำหรือเป็นอนาคต:
- หมวดว่างใน MVP: ข้อความ · รายการ · Arm Control · Car Control · มอเตอร์ · Remote Control
- ตัวละคร/stage (SCR-18) และบล็อกตัวละคร (ขยับ · พูด · เปลี่ยนท่า)
- ตัวจำลองวงจร (SCR-17) ยังเป็นสำเนา: ต่อสาย breadboard, ตัวช่วยต่อสาย (D2), popover อุปกรณ์ (R15), ไฮไลต์อุปกรณ์/ขาในตัวจำลอง (D2), ล็อกปุ่มค้าง (OQ15)
- dropdown อุปกรณ์ผูกกับสายในตัวจำลอง (R16) ขึ้นกับตัวจำลอง
- เสียงตอนวางบล็อก (R14), บันทึกภาพหน้าจอ ("ต้นแบบนี้ยังไม่ได้บันทึกไฟล์จริง"), ตรวจการเชื่อมต่อ/เกี่ยวกับ ("หน้านี้ใช้แบบเดียวกับ Arm Lab ยังไม่ได้ออกแบบใน Block Lab A2")
- token สีหมวด (DSG-13) · ไฟล์ท่ามาสคอตแยก (DEL-09) · รหัส `E-CHK-xx` จริง
- บล็อก Sensor ที่ต้องใช้ไลบรารี (DHT ฯลฯ · "DEV-Q")

## คำถามค้างจาก mockup

1. รายการหมวด: `Spec.dc.html` ยังเป็นชุดเก่า (มี บัส/เสียง/ไฟ/สื่อสาร) แต่ A2 เป็นชุด R18 ใหม่ ต้องยืนยันว่าชุด A2 เป็นของจริง และหมวดตรงกับ toolbox ของ Mixly/engine `mixly` อย่างไร
2. ชื่อหมวดผสมอังกฤษ (Arm Control, Car Control, Sensor, Display, Serial, Remote Control) ขัดกับกฎ Spec เดิม "ไทยสั้น 1 คำ" (OQ62) ต้องตัดสินคำแปล th/en/zh
3. palette: mockup ใช้ CI โทนน้ำเงิน (`#14243D`, `#1866C9`, warn เหลือง) แต่ tokens ในแอปเป็นโทนอุ่น จะเพิ่ม token ใหม่ ปรับ token เดิม หรือใช้เฉพาะ Block Lab · สีหมวด 16 สียังชั่วคราว (DSG-13)
4. หยุดทั้งหมด (DEV-Q16): จะแค่หยุดจำลอง (`stop0` บอกให้ถอดสาย) หรือส่งโปรแกรมว่างลงบอร์ด (`stopA`/`stopB` = อัปโหลด firmware) · ตามกฎ hardware ของ repo การ cancel ไม่เท่ากับ physical stop และการอัปโหลดต้องมีคำสั่งผู้ใช้

6. Ver.1 มีตัวจำลองจริงไหม: A2 ซ่อนแผงแต่ยังมีปุ่มเปิด · ถ้าไม่มีตัวจำลอง R16 (เลขขาจากสาย) และ R17 ข้อ (2)–(4) ทำงานอย่างไร และ dropdown อุปกรณ์เอาข้อมูลจากไหน
7. ตำแหน่งปุ่มเริ่ม/หยุดจำลอง: คอมเมนต์เก่าใน BlocksPaneA2 บอกว่าอยู่แถวลิ้นชัก แต่ Main-A2 (แก้ 2026-10-28) บอกว่าอยู่หัวแผงขวาเท่านั้น ตอนแผงซ่อนต้องเปิดแผงก่อน
8. หมวดว่างใน MVP มี ข้อความ/รายการ ทั้งที่ Mixly มีบล็อกให้ · มอเตอร์ว่างแต่เซอร์โวไปอยู่ Sensor › สั่งงาน (OQ193) ต้องยืนยัน
9. โหมดโค้ดเป็นทางเดียว: ไฟล์งาน (`.sbb`) เก็บทั้งบล็อกและโค้ดที่แก้ไหม · รูปแบบ `.sbb` ยังไม่มีสเปก
